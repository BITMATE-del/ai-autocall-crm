# K-MARKETS — 자체 내부 체결형 거래 플랫폼 아키텍처 (확정)

## 기본 원칙
K-MARKETS는 BITMATE의 **외부 시세 + 자체 내부 체결/정산** 모델을 기준으로 한다.
TradingView 차트에 표시되는 시장가격을 체결 기준으로 삼되, 서버에서는 동일 종목·동일 시장·동일 가격 출처 및 시각을 검증할 수 있는 정식 시세 피드를 사용한다. 차트 위젯의 표시값이나 브라우저가 전송한 값을 신뢰하지 않는다. Binance 등 외부 API는 시장 데이터 용도로만 사용하며 **고객 실주문을 외부 거래소로 전달하지 않는다.** 외부 거래소 계정·트레이딩 API Key는 필요하지 않다.

## 주문 및 정산의 신뢰 경계
- 브라우저는 주문 의사를 전달하고 서버가 확정한 체결/잔고/포지션/거래내역만 표시한다. 브라우저의 localStorage/타이머/차트 값을 정산 권한으로 사용하지 않는다.
- 로그인과 세션 인증, 상품 활성 상태, 거래 가능 시간, 최소·최대 수량/금액, 잔액, 중복 주문 방지 키, 제한 상태를 서버가 검증한다.
- 시장 데이터 수신기는 시세 출처, 수신시각, 신선도, 이상치/재연결 상태를 관리한다. 시세가 오래되거나 검증 불가하면 신규 주문/만기 정산을 안전하게 보류한다.
- 주문 접수·잔액 잠금·체결·원장 기표는 DB 트랜잭션으로 원자적으로 실행한다. 멱등성 키와 고유 제약, 잠금 또는 낙관적 버전검사를 적용한다.
- 포지션 관리, 수수료, 손익과 만기 확정은 서버 전용 프로세스가 처리하고 각 변경의 감사 로그를 기록한다.
- 잔액은 불변의 이중기입 원장에서 파생하며 정정은 기존 기록 수정 대신 반대 분개로 처리한다. 일일 대사와 불일치 경보를 운영한다.
- 회원별 계좌·거래내역은 RLS/서버 권한으로 분리하고 관리자 정정도 승인·감사 대상이다.

## 상품별 분리
1. **국내주식 현물형 내부 체결:** 지정가·시장가, 호가/체결 규칙, 거래 가능 시간과 수수료, 매매 후 보유자산의 의미를 명시. 이 구조가 실제 증권 소유권 이전을 의미하지 않음을 정확히 고지한다.
2. **코인 CFD:** BITMATE 3분·5분 상승/하락형 주문과 WIN/LOSS/DRAW 만기 규칙을 별도 엔진에 구현. 체결가 기준·만기 시각·가격 참조·비김 처리·수수료 정책을 서버에서 고정한다.
3. **기타 상품:** 각 상품 자체 체결·손익·정산 정책과 버전 관리.

## 시스템 구성
Next.js(UI) → 인증 API → 주문 서비스 → PostgreSQL 원장/포지션/주문 저장소
시장 데이터 피드(외부 시세 전용) → 검증/시각 동기화 → 서버 체결/정산 서비스
체결/정산 이벤트 → 권한 확인된 실시간 갱신 → 회원 화면
별도 작업 프로세스/Queue → 만기 정산, 재시도, 대사 및 경보

## 공개 서비스 개시 전 필수 게이트
- 개발/샌드박스/운영 계정 및 원장 분리, 전 구간 TLS, 비밀정보 관리, 최소 권한, 감사/백업/재해복구
- 주문 경쟁 상태, 멱등성, 중복 정산, 시세 중단, 프로세스 재기동 및 장애 복구 테스트
- 실제 자금 취급 시 법률상 인허가, 이용자산 보호·자금세탁방지, CFD 및 국내주식 관련 금융규제 검토
- 서비스 설명에서 내부 체결과 이용자 거래 상대방, 실제 금융상품의 소유·보유 여부 및 위험을 명확히 고지
- **운영 미준비 상태의 UI나 API를 실제 체결 가능하다고 표시하지 않는다.**

## 현재 구현 상태 (2026-10-20)
현재 Railway 사이트는 차트/시세와 브라우저 로컬 체험형 거래 UI를 갖춘 프로토타입이다. 서버 주문·원장·정산 엔진은 아직 연결되지 않았으므로 실제 자금을 받거나 운영 거래로 취급하지 않는다. 기존 코드는 정책이 충족되기 전까지 보존하고, 검증된 새 엔진으로 단계적으로 대체한다.


## 2026-10-20 운영주체 및 시세 기준 확정
- K-MARKETS와 BITMATE는 동일 운영주체의 서비스이며 상품별 거래 정책과 내부 체결·정산 규칙을 동일하게 유지한다.
- TradingView 화면에서 표시하는 해당 종목의 시세를 **기준가격의 목표**로 삼는다. 다만 TradingView 임베드 자체를 정산 오라클로 사용할 수 없으므로, 동일 데이터 공급원과 심볼 매핑·수신 시각·호가/종가 기준을 서버에 명시해야 한다.
- 서버 체결 결과와 고객 표시가격의 일치성 테스트가 완료될 때까지 실제 거래는 활성화하지 않는다.
- 회원용 화면에서 '체험용' 등 표현은 쓰지 않되, 실제 서버 주문이 아직 연결되지 않은 상태는 정확히 알린다.
